# Portable runtime contracts from CAW 1.2

Pi supports node-scoped executable activation, automatic completion checks, directory-isolated Main worker fan-out, declared shared prefixes, bounded text amendments and explicit current-Main acceptance loops. Execution uses Pi sessions and actual JSONL turn IDs. Source snapshots and existing Run pins are unchanged by adapter upgrades.

Scoped dependencies activate when their node is selected. Global and selected-node requirements are intersected, executable paths are verified, and the selected scope and path digest are pinned to its lease. An inactive conditional branch does not require its optional executables. Unavailable selected dependencies retain node/source requirement evidence and stop dispatch.

Automatic checks resolve their own declared inputs on the Host. Each proposed Pi turn/item has a durable check intent before effects, an exact receipt before admission, and content-addressed input/output evidence. Accepted filesystem effects are sealed and checked again before completion. Replaying the same check reads its evidence without invoking the implementation. Uncertain effects block replay, new attempts and retention until their actual ownership is reconciled. Semantic rejection remains correction data; mechanical errors remain visible errors. Correction budgets are per current loop round and, for fan-out, per item.

Main worker fan-out inherits the initiating Pi model and thinking. Each `one_per_item` assignment receives an existing Host-owned directory and intersected write grant. Overlapping item directories and writes outside an item directory fail before dispatch. Accepted siblings survive a reconciled local retry and do not run again. The final aggregate reproduces journaled positional item results and actual session/turn receipts.

`shared_prefix.common_inputs` is a semantic declaration: Pi stores the selected common inputs and pinned resource identities and supplies that contract to fresh item sessions. The receipt explicitly records `transport_cache: false`. This does not imply provider prompt caching, a shared model context or a preparatory model turn.

Text corrections use sealed physical-line scopes from the checker. The Host applies bounded amendments to the original semantic text, retaining every unrelated field and line. Pi amendment turns expose semantic submission and pinned resource reads only; filesystem and program tools are blocked. The checker reruns on the Host-applied text.

`review_context: current_main` declares read-only acceptance in the initiating Pi conversation by default. An explicit frozen Run `main_modes` worker override may use an isolated Main execution while retaining its initiating actor, original inputs, read-only scope, acceptance gate, feedback and round policy. The receipt distinguishes logical Main ownership from the actual execution thread. The exit must declare and gate release on `accepted: true`; its mechanical effects and fan-out are forbidden. Only this explicit source mode permits `max_rounds: null`. Ordinary loops retain finite bounds and fresh read-only review. Cancellation settles the exact Pi owner and does not release final acceptance. Neither Main mode requires the Run workspace to equal the chat cwd; current-chat packets and prompts carry the authorized workspace explicitly.

The generic resource-program adapter explicitly qualifies the finite pinned interface under its supported protocol. It executes only exact declared resource bytes under the intersected write grant, preserves the foreign source identity and records the current Pi adapter identity in the receipt. Logical executable paths and the declared process environment reach child processes through the Pi broker. Resource-program and remote Host ownership include the exact automatic-check execution slot, so concurrent sibling checks do not share a cancellation owner.

Current capability boundaries are visible during library validation and startup: directory-isolated `workspace_field` fan-out requires `one_per_item`; a partition spanning multiple item directories is unsupported. Independent Role launch does not execute Workflow fan-out, completion checks or loops and rejects such Role graphs. Shared-prefix transport caching is not claimed. A missing Main adapter, missing isolated-Main capability or incompatible Host tool is a local readiness blocker.

Verification uses fictional graphs and temporary state, including the real offline Pi SDK with a faux provider. `test/portable-runtime.test.mjs` exercises correction/admission/replay, uncertainty, filesystem staleness, accepted siblings, scoped dependencies and loop acceptance/cancellation. `test/portable-runtime-sdk.test.mjs` verifies inherited models, exact JSONL turns, amendment tool restrictions and a cross-host resource program with filtered environment and observed artifacts. No private workflow resources or real owner state are repository fixtures, and these checks make no paid model calls.
